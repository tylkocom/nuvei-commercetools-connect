<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| browser SDK→enabler | Nuvei browser result is shopper-visible and not authoritative; it must not independently produce approved completion. |
| enabler→processor `/payments/confirm/:id` | Enabler sends known session token and payment reference to backend for authoritative classification. |
| processor response→merchant callbacks | Minimal `{ outcome }` determines merchant-visible callback behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-01.1.1-06 | Tampering | `confirmPaymentResult()` | mitigate | Require approved processor outcome before calling onComplete; browser result cannot create false approved. |
| T-01.1.1-07 | Denial of Service | pending callback flow | accept | Pending is surfaced once via optional onPending; polling is not implemented in this phase per D-22/D-25. |
| T-01.1.1-08 | Information Disclosure | rejected onError | mitigate | Use a safe payment rejected error; do not expose raw Nuvei status, session token, or diagnostics. |
| T-01.1.1-09 | Spoofing | sessionToken source | mitigate | Confirm with sessionToken from processor createPayment response, not untrusted/missing browser result fields. |
| T-01.1.1-SC | Tampering | npm installs | accept | No package installs in this plan. |
</threat_model>
