<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| browser→processor `/payments/confirm/:id` | Shopper-controlled browser submits session token and Payment reference; session auth and cart ownership must be enforced. |
| processor→Nuvei getPaymentStatus | Processor trusts only server-side verified Nuvei status fields; official status may omit canonical PPP. |
| processor→commercetools Payment mutation | Only canonical and validated terminal outcomes may mutate CT Payment transactions. |
| Nuvei DMN→processor converter | DMN body supplies identity/status fields; checksum/config/payment validation must precede mutation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-01.1.1-01 | Tampering | `confirmPayment()` browser result/status | mitigate | Ignore browser terminal status as authority; call Nuvei getPaymentStatus and classify server-side per D-08/D-09. |
| T-01.1.1-02 | Elevation | `assertSessionPaymentAccess()` | mitigate | Keep cart ownership and session-token checks before any confirm outcome or CT mutation. |
| T-01.1.1-03 | Tampering | CT Authorization `interactionId` | mitigate | Permit terminal writes only with PPP_TransactionID/PPP_TransactionId/ppp_TransactionID; reject sessionToken and fiscal fallback. |
| T-01.1.1-04 | Repudiation | Duplicate confirm/DMN | mitigate | Deduplicate by canonical PPP interactionId, not arbitrary terminal Authorization or optional fiscal TransactionID. |
| T-01.1.1-05 | Information Disclosure | Confirm route body/logs | mitigate | Public response remains `{ outcome }`; detailed Nuvei/session diagnostics stay in redacted logs. |
| T-01.1.1-SC | Tampering | npm installs | accept | No package installs in this plan. |
</threat_model>
