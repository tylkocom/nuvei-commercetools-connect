## Response contract

| Option | Description | Selected |
|--------|-------------|----------|
| Minimal outcome union | `{ outcome: 'approved' | 'rejected' | 'pending' }`. Small, stable, safe. Details stay in logs. | ✓ |
| Outcome + retry hint | `{ outcome, retryAfterMs? }`. Gives the enabler a processor-owned polling cadence for pending. | |
| Outcome + reason code | `{ outcome, code?, message?, retryAfterMs? }`. More useful for UI, but creates a public error/status contract now. | |

**User's choice:** Minimal outcome union.
**Notes:** Public response remains safe and small.

## Nuvei status mapping

| Option | Description | Selected |
|--------|-------------|----------|
| Strict known mapping | APPROVED => approved; known final declines/cancel/expired/error => rejected; all unknown/action-required/processing => pending. | ✓ |
| Conservative pending | APPROVED => approved; only explicit hard decline => rejected; everything else => pending until DMN/sandbox evidence proves finality. | |
| Reject all non-approved | APPROVED => approved; everything else => rejected. Simple but causes false failures for pending/3DS/async flows. | |

**User's choice:** Strict known mapping.
**Notes:** Unknown or unevidenced states must not be classified as rejected; researcher must confirm actual Nuvei values.
