<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser/enabler → Processor `/payments` | Untrusted method options cross into backend before payment state creation. |
| Processor route → Nuvei API | Request becomes external Nuvei order/session state at `openOrder`. |
| Processor service → commercetools Payments | Request becomes commercetools Payment state during CT Payment creation and cart association. |
| Processor → Operator logs | Diagnostics leave request handling path and must be redacted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-SPOOF | Spoofing | `processor/src/routes/nuvei-payment.route.ts` | mitigate | Keep `SessionHeaderAuthenticationHook` on `/payments`; classify safe auth/session errors without exposing session details. |
| T-01-02-TAMPER | Tampering | `PaymentMethodOptionsSchema`, `validatePaymentMethodOptions` | mitigate | Reject malformed, multiple-key, and unsupported method options before service orchestration. |
| T-01-02-REPUD | Repudiation | `NuveiPaymentService.createPaymentIntent` | mitigate | Log redacted category/route/requested method for invalid setup while avoiding external state creation. |
| T-01-02-INFO | Information Disclosure | Public route errors and processor logs | mitigate | Return only `{ code, message }`; never log secrets, checksums, session tokens, PAN-adjacent values, or raw payloads. |
| T-01-02-DOS | Denial of Service | `/payments` body parsing | mitigate | TypeBox schema rejects unexpected method-option shapes early with bounded object shape. |
| T-01-02-SC | Tampering | npm installs | accept | No package installs are planned; Phase 1 uses existing dependencies and package-local npm tests only. |
</threat_model>
