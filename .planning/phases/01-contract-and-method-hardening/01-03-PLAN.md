<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Processor registry ↔ Enabler registry | Mirrored package-local contracts can drift because no shared module is used. |
| Processor `/payment-components` ↔ Checkout/enabler | Advertised methods influence what Checkout/enabler attempts to build and process. |
| Contract tests ↔ payment state side effects | Regression coverage must prove unsupported inputs cannot create external payment state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03-TAMPER | Tampering | Mirrored registries | mitigate | Cross-package parity tests fail on method key, kind, advertised type, transitional marker, or PSP metadata drift per D-06. |
| T-01-03-REPUD | Repudiation | `/payment-components` advertised contract | mitigate | Route and parity tests provide executable evidence for every advertised method. |
| T-01-03-INFO | Information Disclosure | Error contract regression tests | mitigate | Tests assert public unsupported errors are safe code/message only where route coverage is available. |
| T-01-03-DOS | Denial of Service | Unsupported method handling | mitigate | No-side-effect tests reject unsupported methods before costly Nuvei/CT Payment calls. |
| T-01-03-SC | Tampering | npm installs | accept | No package installs are planned; Phase 1 uses existing dependencies and package-local npm tests only. |
</threat_model>
