  <files>

  <action>
    Edit enabler/src/services/api-service.ts. All changes are in this single file.

    1. PaymentSessionResponse type (per D-15): add cartId field.
       Before:
         export type PaymentSessionResponse = {
           sessionToken: string;
           paymentReference: string;
           merchantReturnUrl?: string;
         };
       After:
         export type PaymentSessionResponse = {
           cartId: string;
           sessionToken: string;
           paymentReference: string;
           merchantReturnUrl?: string;
         };
       cartId is string (not optional) — the processor always returns it in the session response.
       Downstream consumers (card.ts, dropin-embedded.ts) read sessionToken and paymentReference;
       adding cartId is additive and does not require changes in those files.

    2. ConfirmPaymentResponse JSDoc comment (per D-02): update "POST /payments/confirmPayments/:ref"
       to "POST /payments/confirm/:ref" in the comment above the type definition.

    3. ApiService type (per D-05): remove getPayment from the type.
       Before:
         export type ApiService = {
           createPayment: (opts?: CreatePaymentRequest) => Promise<PaymentSessionResponse>;
           getPayment: () => Promise<PaymentSessionResponse>;
           confirmPayment: (opts: ConfirmPaymentRequest) => Promise<ConfirmPaymentResponse>;
         };
       After:
         export type ApiService = {
           createPayment: (opts?: CreatePaymentRequest) => Promise<PaymentSessionResponse>;
           confirmPayment: (opts: ConfirmPaymentRequest) => Promise<ConfirmPaymentResponse>;
         };

    4. createPayment() method URL (per D-05): change from /payments to /payments/session.
       Before:
         const res = await fetch(`${baseApi}/payments`, {
           method: "POST",
           ...
         });
       After:
         const res = await fetch(`${baseApi}/payments/session`, {
           method: "POST",
           ...
         });
       Also update all two error diagnostic route strings in the method body:
         route: "POST /payments" → route: "POST /payments/session"
       (These appear in the PaymentSetupError constructors in the not-ok branches.)

    5. getPayment() method: remove the entire method implementation from the returned object
       in apiService(). It is the async function that fetches ${baseApi}/payments via GET.
       Confirmed dead code: neither card.ts nor dropin-embedded.ts calls api.getPayment().

    6. confirmPayment() URL (per D-02): change path from
         `${baseApi}/payments/confirmPayments/${params.paymentReference}`
       to:
         `${baseApi}/payments/confirm/${params.paymentReference}`
       The method name confirmPayment(), its signature, and its error handling are unchanged.

    DO NOT change:
    - confirmPaymentResult() function (uses api.confirmPayment() which is unchanged)
    - The X-Session-ID header logic
    - Any error types or PaymentSetupError usage
