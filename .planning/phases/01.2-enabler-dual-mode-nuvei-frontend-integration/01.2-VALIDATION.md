# Phase 1.2: Enabler Dual-Mode Nuvei Frontend Integration — Validation

**Created:** 2026-06-03
**Status:** Ready for execution

## Validation Architecture

Phase 1.2 splits dual-mode Nuvei frontend integration across three execution waves. Each wave proves its own contract before the next wave consumes it.

### Wave 1: Independent contract cleanup and harness scaffolding

**Plans:** `01.2-01-PLAN.md`, `01.2-02-PLAN.md`, `01.2-03-PLAN.md` (parallel)

**Plan 01 — Processor card-only contract**

Primary risks validated:
- Processor `PAYMENT_METHOD_REGISTRY` contains only `card`; `embedded` is removed.
- `DropinType` enum no longer contains `EMBEDDED`.
- `GET /payment-components` returns `{ dropins: [], components: [{ type: 'card' }] }`.
- `isSupportedPaymentMethod('embedded')` returns false.
- Cross-package parity test file compiles with card-only assertions (full pass deferred until Wave 3).

Automated check:

```bash
cd processor && npm run build
cd processor && npx tsc --noEmit
```

**Plan 02 — Enabler loader split and card-only registry**

Primary risks validated:
- `simply-connect-sdk.ts` replaces ambiguous `nuvei-sdk.ts`; SC loader exports `loadSimplyConnectSdk`.
- `dropin-embedded.ts` and `dropin.test.ts` are deleted; enabler registry is card-only.
- `card.ts` imports from `simply-connect-sdk.ts` (not deleted `nuvei-sdk.ts`).
- Remaining enabler unit tests pass: `card`, `api-service`, `simply-connect-sdk`.

Automated check:

```bash
cd enabler && npx vitest run test/unit/card.test.ts test/unit/api-service.test.ts test/unit/simply-connect-sdk.test.ts --reporter=verbose
cd enabler && npx tsc --noEmit
```

**Plan 03 — Examples harness migration**

Primary risks validated:
- `examples/nuvei-web-ui/` exists as a self-contained npm package with `start`, `test:api`, `tunnel:dmn` scripts.
- Mock CT server, DMN tunnel, and API e2e scripts are migrated from `testing/`.
- Postman assets, old HTML guides, and `testing/` directory are removed.
- `npm install` in `examples/nuvei-web-ui/` succeeds.

Automated check:

```bash
cd examples/nuvei-web-ui && npm install
ls testing/ 2>&1 || echo "testing/ removed"
```

### Wave 2: Web SDK card path and mode-aware enabler classes

**Plan:** `01.2-04-PLAN.md`

Primary risks validated:
- `web-sdk.ts` loader owns `window.SafeCharge`, deduplicates script injection, and does not import from `simply-connect-sdk.ts`.
- `WebSdkCardBuilder` has `componentHasSubmit=true`; `submit()` calls `sfc.createPayment()` with `paymentOption=scard` instance.
- Web SDK result normalizer reads `res.result` (not `res.transactionStatus`).
- `SimplyConnectCardBuilder` retains `componentHasSubmit=false`; `submit()` still throws.
- `NuveiSimplyConnectEnabler`, `NuveiWebSdkEnabler`, and mode-required `NuveiEnabler` facade are exported from `index.ts`.
- Facade rejects missing/unsupported mode before `validateEnablerOptions`, processor fetch, or SDK load.
- Sandbox placeholder `billingAddress` is annotated with a `SANDBOX-ONLY` comment referencing Phase 4.

Automated check:

```bash
grep -q 'SANDBOX-ONLY.*Phase 4' enabler/src/components/web-sdk-card.ts

```

## Wave Gaps

The following behaviors are **not unit-testable within Phase 1.2** and require Phase 2 sandbox evidence capture or manual browser verification:

| Gap | Why not unit-testable in Phase 1.2 | Deferred to |
|-----|-------------------------------------|-------------|
| Real Nuvei sandbox payment approval/decline through Web SDK `createPayment()` | Requires live `safecharge.js`, Nuvei sandbox credentials, and real card data | Phase 2 sandbox evidence |
| 3DS challenge / frictionless flow end-to-end | Browser-managed 3DS UI cannot be exercised with mocked SDK stubs alone | Phase 2 sandbox evidence |
| `scard.attach()` field-render readiness timing | Docs show no await/callback; whether `submit()` is safe immediately after attach is unconfirmed | Phase 2 first sandbox run |
| Exact required vs. optional `createPayment()` fields for sandbox approval | Quick-start docs show example fields but do not specify minimal required set | Phase 2 first sandbox run |
| Simply Connect `onResult` field name (`transactionStatus` vs `result`) against live callback | Current unit tests mock the expected shape; live Nuvei callback may differ from docs | Phase 2 sandbox capture |
| CDN script loading against real `checkout.js` / `safecharge.js` | Unit tests stub `window.checkout` / `window.SafeCharge`; no network or SRI validation | Phase 2 / Phase 5 |
| Example UI mode selector exercising both modes in a real browser | `index.html` wiring is verifiable by grep; payment flow requires browser + processor + mock CT server | Phase 2 manual evidence |
| DMN tunnel and webhook delivery to processor | Local tunnel tooling is migrated but webhook round-trip is integration-level | Phase 2 evidence harness |
| Production-grade shopper/billing data sourcing | Phase 1.2 uses `SANDBOX-ONLY` placeholder data by design | Phase 4 |
