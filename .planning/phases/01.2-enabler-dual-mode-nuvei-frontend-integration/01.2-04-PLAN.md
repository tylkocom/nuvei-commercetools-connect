<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| NuveiEnabler mode validation | Mode must be validated before any network call or SDK script injection |
| Web SDK sessionToken | Must come from processor POST /payments/session response, never from SafeChargeResult callback |
| Simply Connect vs Web SDK loaders | Two distinct globals (window.SafeCharge vs window.checkout); must not share load promise |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.2-04a | Tampering | Web SDK sessionToken sourcing | mitigate | Use paymentRes.sessionToken from processor response, never from sfc.createPayment() callback (per D-11) |
| T-01.2-04b | Information Disclosure | Sandbox placeholder billing data in Web SDK component | mitigate | Label with "SANDBOX-ONLY" comment; Phase 4 owns real data sourcing (D-20) |
| T-01.2-04c | Elevation of Privilege | NuveiEnabler mode validation bypass | mitigate | Mode validation throws in constructor before validateEnablerOptions and before any processor URL call or SDK load |
| T-01.2-04d | Tampering | paymentOption: "card" string passed to createPayment | mitigate | Always pass scard instance (SafeChargeCardField), never the string "card" — enforced by TypeScript type (paymentOption: SafeChargeCardField) |
| T-01.2-04e | Tampering | wsLoadPromise shared with scLoadPromise | mitigate | Each loader module has its own distinct module-scope variable; verified by loader isolation test |
| T-01.2-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed |
</threat_model>
