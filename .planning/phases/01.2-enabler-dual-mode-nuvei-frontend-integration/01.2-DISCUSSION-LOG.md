## Component Architecture

| Question | Options | Selected |
|---|---|---|
| Source folder structure | Mode-first folders / Type-first folders / Shared core + adapters | Type-first folders, but refactor the current mess |
| Shared boundary | Infrastructure only / Abstract component base / Share everything possible | Share infrastructure only after assistant challenged over-sharing risk |
| SDK loader split | Separate loader modules / One mode-parameterized loader / Current loader plus helper | Separate loader modules |
| Result normalization | Inside each adapter / Central normalizer / No normalization | Inside each adapter |

**Notes:** User initially chose “share everything possible”; assistant pointed out this risks encoding Simply Connect assumptions into Web SDK lifecycle/result/3DS behavior. User accepted the safer boundary: share infrastructure only (`apiService`, session creation, confirm helper, mount helpers), keep SDK/render/result interpretation separate.
