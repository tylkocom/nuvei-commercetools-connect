<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Processor → mock CT ledger | The real processor sends session/cart/payment/auth requests to a local CT-compatible mock instead of real commercetools. |
| Processor → Nuvei sandbox | Stage A creates real Nuvei openOrder/session state. |
| Raw capture workspace → committed evidence | Processor responses, mock ledger snapshots, and Nuvei-derived fields cross into evidence through sanitizer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-02-02-01 | Spoofing | Mock CT Session/OAuth endpoints | accept | Local-only evidence stage; index environment labels `nuvei-sandbox-local-mock-ct` and validator prevents NUV-07/NUV-08 pass from this environment. |
| T-02-02-02 | Information Disclosure | `ledger.lastRequests` and raw captures | mitigate | Store request logs only in gitignored raw workspace or memory; sanitize before committed evidence; validator scans evidence output. |
| T-02-02-03 | Tampering | CT-like Payment shape | mitigate | Mock self-check asserts native CT Cart/Payment fields used by current processor: interfaceId, amountPlanned, paymentInfo, transactions, paymentStatus, and versions. |
| T-02-02-04 | Denial of Service | Nuvei getPaymentStatus/openOrder usage | mitigate | Stage A performs one session/openOrder capture and does not poll confirm/status. |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages are installed or added by this plan. |
</threat_model>
